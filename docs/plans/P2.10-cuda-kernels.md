## Implementation decisions

### Preserve the P2.9 contract

Implement all eight ABI entry points: four forward operations and their backwards. Retain spec
version 1, contiguous row-major storage, int32 ABI indices, exact erf GELU, and fp32 accumulation
for f16/bf16. Use the header's completed backward equations, especially the gated update's
`grad_h_selected = (1-b)*grad_h_out - b*grad_q_out/N` coupling. Write every gradient output in
full, including zeros for absent units and padded slots.

Preserve repeated-index accumulation in gather/messages, empty CSR rows, ignored invalid padded
indices, unique valid update indices, and exact integer outputs. RMSNorm, alpha mixing,
candidate normalization, gate, `W_out`, and tanh remain host model operations as specified by
the current ABI. Ages reset in the kernel; the model performs its existing tick.

### Training and in-place state updates

The installed PyTorch source at `torch/_library/custom_ops.py:742` rejects registering an
autograd formula for a nonfunctional operator. The existing native sparse path also returns a
new `CellGraphState` during training.

Retain the specified `hsn::gated_delta_update` mutation schema for the low-level in-place path.
Add a functional training custom-op wrapper that returns fresh state tensors and saved old
selected states, and register its backward with `torch.library.register_autograd`. It can call
the same CUDA update on private output buffers. Never mutate a previous training state needed
by another timestep. Use the in-place entry point only where state ownership permits it under
`no_grad`; preserve intermediate diagnostics and pre-round reads in the existing sparse step.

Register FakeTensor implementations and traceable backward custom ops for all training
operations. Saved implementation intermediates must have explicit differentiation behavior.
Check registration and compiled forward/backward behavior with
[PyTorch opcheck](https://docs.pytorch.org/docs/2.15/library.html#torch.library.opcheck), and
check numerical derivatives separately.

### One device binary, two hosts

Build one `build/hsn_ops.fatbin` from `kernels/cuda/hsn_ops.cu` containing explicit device entry
points. Keep host C-ABI wrappers and launch orchestration in the extension host layer, with
corresponding launches in the Rust backend. Both hosts load the same fatbin on a given machine.
Host wrappers are required because
[nvcc --fatbin](https://docs.nvidia.com/cuda/cuda-compiler-driver-nvcc/index.html#fatbin-fatbin)
discards host code; the header's status-returning C functions are not themselves device kernels.

Compile SASS for `sm_80, sm_86, sm_89, sm_90, sm_120, sm_121`, plus `compute_120` PTX. Exclude
`sm_120a`; check nvcc target support explicitly. Build before import, resolve module/functions
before graph capture, and retain them through the lifetime of captured graphs. No import-time
extension compilation or NVRTC. Separate the mandated PTX compatibility fallback from runtime
source compilation; require native SASS on the tested 3060 and Spark profiles.

Use the calling PyTorch device/current CUDA stream and the Rust backend's supplied stream.
Preallocate or warm up all scratch/handles before graph capture; fixed input shapes and routing
changes must not cause host synchronization, dynamic allocation outside the graph allocator,
recompilation, or stale scratch reuse across streams.

### Selected-unit MLP and deterministic reductions

Start with CUDA kernels that execute only each selected unit, with tiled reductions and a
fused bias/exact-GELU pass. Keep routing/grouping on the GPU. Deterministic backwards use a
fixed order per-unit/per-output reduction with fp32 accumulation and no floating-point atomics;
gather and CSR backwards need this too. A faster atomic path may be measured separately.

cuBLAS is an optional measured optimization, not a prerequisite for the first correct path.
The installed header declares `cublasGemmGroupedBatchedEx`, but its
[group sizes and dimensions are host arrays](https://docs.nvidia.com/cuda/cublas/index.html#cublasgemmgroupedbatchedex).
Inference: reading dynamic selected-unit counts back to construct those arrays would conflict
with graph capture. Only adopt a cuBLAS layout with static host metadata, device-side pointer
selection, and proven capture/parity behavior. Benchmark it against the direct selected-unit
implementation before choosing it.

### Adapt the existing model without changing its equations

- Add CUDA dispatch in `python/hsn/kernels/__init__.py`, with explicit availability errors and
  CPU/MPS native behavior. Select the backend before compiling a window. Report any deliberately
  disabled CUDA operation and its measured reason.
- Implement adapters in `ops.py` for the current `KernelOps` protocol, including `static`,
  `w1_flat`, `weights`, and `validate` arguments.
- Convert Python int64 indices/ages and bool masks to int32 ABI inputs on device and restore
  public state dtypes. Validate representable extents/ranges outside capture; prevent age
  overflow rather than narrowing silently. Invalid padded indices remain ignored.
- The compiled window supplies padded graph weights `[N,D_max]`, while the ABI takes `[E]` in
  CSR order. Map using the graph's existing edge-position mapping while preserving gradients
  through normalized weights. Cache topology metadata only with proper invalidation.
- Preserve autocast behavior: fp32 recurrent state, autocast MLP/messages, state-dtype gather
  and update, fp32 master parameter gradients. Cast parameters per call as needed so gradients
  across a window do not accumulate into a cached bf16 parameter copy.

### Rust ownership

The current `Backend` argument types contain host slices. Do not reinterpret a CUDA device
address as one of those slices. Implement `CudaBackend` with owned device buffers and explicit
resident launch methods; provide a staging adapter for the existing host-slice trait and vector
tests. Transfers and synchronization belong at that adapter's boundaries and must be excluded
from resident-kernel timings, then reported separately.

Add cudarc as an optional dependency with default features disabled and driver/dynamic-loading
support enabled. Its [default features include NVRTC](https://docs.rs/crate/cudarc/latest/source/Cargo.toml),
so audit the resolved feature graph and linked artifacts. Resolve the exact no-NVRTC binary
module-loading API in the pinned version during the initial build; use the driver API if its
high-level loader requires an unwanted feature. Keep CUDA off for ordinary workspace builds.
